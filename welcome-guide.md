# Welcome to the Software Engineering Collective

**Purpose:** Explain how a new member begins participating in SEC projects.

**Intended audience:** New SEC members.

**Last updated:** 2026-09-30  
**Owner:** President

## What SEC does

SEC builds real software projects using a shared engineering workflow. Members learn by contributing to issues, working in pods, opening pull requests, reviewing work, and documenting decisions.

You do not need to know every tool before joining a task. Start with a small, well-defined issue and ask for help early.

## Where things live

| Place | Use it for |
|---|---|
| Discord | Announcements, pod communication, questions, and blockers |
| GitHub Organization | Repositories, issues, pull requests, and published standards |
| GitHub Project | Sprint tasks, ownership, and work status |
| Google Drive | Working documents, meeting notes, research notes, and templates |

## Your first steps

1. Join the GitHub organization with your GitHub username.
2. Choose a pod: Frontend, Backend, DevOps, or QA.
3. Read your pod's pinned Discord message.
4. Read the [Engineering Glossary](../glossary.md).
5. Read the [Git Workflow](../engineering-standards/git-workflow.md).
6. Find a small task in the Project board's **Ready** column.
7. Assign yourself only when you understand the acceptance criteria.

## How to get help

Ask in your pod's Discord channel when you are blocked. Include what you were trying to do, what you tried, and the error or result you received.

Being blocked is normal. Leaving a blocker invisible is what slows down a project.
